# PCNME dataset: datasheet

Results, trained models and logs of PCNME (Predictive Cloud-Native Mobile Edge), the MSc thesis of
Imed-eddin Benmadi (ELTE, 2026). PCNME places the computing tasks of moving cars across fog zones and the
cloud: a fixed rule (the TOF-Broker) sends tasks too heavy for any fog node to the cloud, and a D3QN agent in
every zone places the rest, pretrained (DQfD) on NSGA-II knee-point plans and then learning online.

- **Code:** https://github.com/imadbenmadi/pcnme-src (tag `results-v1`), MIT licence. Every file here can be
  regenerated from the code, the config (`config/default.yaml`) and the seeds below.
- **Data licence:** CC BY 4.0 (LICENSE-DATA.txt). Cite the record's DOI.
- **Design:** `docs/final-design.md` in the repository (the specification); symbols in `docs/NOTATION.md`.
- **Log schema:** METRICS.md (copied here): every Parquet table and column, with units.

## What was run

Two city maps, the same 1.2 × 1.2 km layout with 4 active fog zones and 200 cars:

- **vfc**: the VFC paper's road grid (generated by code).
- **lust**: a crop of central Luxembourg from the LuST SUMO scenario (Codeca et al. 2015, MIT licence),
  replayed from SUMO traces. The LuST scenario itself is not included: cite it.

Six scenarios (S1 light, S2 critical, S3 overload, S4 tight deadlines, S5 high mobility, S6 mixed fog), eight
methods (pcnme, d3qn-greedy, d3qn-scratch, vfc-ppo, tang-wong, qeco, greedy, random). Fast mode (the
discrete-event simulator) for training and evaluation: 20 evaluation seeds per scenario and method. The Docker
testbed (real MQTT, HTTP, emulated network) for VFC only: 5 seeds, 40 cars.

**Seeds** (disjoint, `fast_mode.seed_split`): 1000–1999 NSGA-II plans and demonstrations, 2000–2999 training,
3000–3999 evaluation (3000–3019 in fast mode, 3000–3004 on the testbed).

## Files

All paths inside the zips start at `data/`, as in the repository.

| File | What | Main contents |
| --- | --- | --- |
| `<map>-meta.zip` | the map's run identity | `manifest.json` (what was trained, with config hash and commit), `w_star.json` (the deployed reward weight w*), `calibrated.yaml` (LuST: measured coverage and hotspot share) |
| `<map>-results.zip` | the reported results | `summary.csv` (one row per evaluation run: every metric), `report.csv`/`.md` (mean and 95 % interval per scenario and method), `paired.csv`/`.md` (paired t tests of PCNME vs each method), `extra-*.csv` (predictor accuracy, T_exit error, hypervolume), `reproduce.md`, the figures (`*.png`); `archive/` the earlier S6 with tight deadlines (a stress test) |
| `<map>-runs-S1.zip` … `-S6.zip` | every evaluation run, task by task | `results/runs/<scenario>-<method>-<seed>-fast/`: `tasks`, `attempts`, `decisions` (the agent's 48 inputs and its action), `transitions`, `zones`, `pipes`, `positions`, `events` (Parquet; METRICS.md) and `run.json`. The task stream of a seed (arrival, car, zone, type, size, deadline) is in `tasks.parquet` of any method's run with that seed: arrivals do not depend on decisions. |
| `<map>-train.zip` | training of the six learning methods | `train/<scenario>-<method>/`: `trained.pt`, `model.pt` (PyTorch weights), `episodes.csv` (the training curve), `training.json`, `train.log` |
| `<map>-nsga.zip` | the NSGA-II expert | `nsga/<scenario>-w<k>.json`: every window's final front (every plan's genome and objectives), its knee and weight; `fronts.csv` one row per window |
| `<map>-demos.zip` | the demonstrations | `demos/<expert>-<scenario>-w<k>.parquet`: the replayed transitions (s, a, r, s′, Δt) used for pretraining; `demos.csv` a summary |
| `vfc-testbed.zip` | the Docker testbed (VFC) | `testbed/results/<run>/` the same tables as fast mode, `summary.csv`, `gap.csv`/`.md` (testbed vs fast mode), `archive/` earlier batches replaced by fixed reruns, `live/` the live demonstration runs (not measurements) |
| `vfc-archive.zip` | an archived training | `_archive/`: the S6 training with tight deadlines behind `results/archive/` |
| `lust-traces.zip` | the LuST vehicle traces | `traces/<time of day>.npz` + `.json`: positions every 100 ms on the crop (from SUMO; regenerated by `train.py --maps lust --until traces`) |
| `lust-logs.zip` | the LuST training log | |
| `calibration.zip` | the measured time table | `calibration/calibration_*.json`: run times (mean, p5, p95, longest step) and energy per run of YOLO on a GTX 1070, per task type and slot type; `cpu-power.md` |
| `DATASHEET.md`, `METRICS.md`, `LICENSE-DATA.txt`, `SHA256SUMS.txt` | this sheet, the log schema, the licence, checksums of every file | |

## Units and names

SI units: seconds, bits, bits per second, watts, joules, metres (a column name says otherwise when it does:
`latency_ms`, `input_kb`). Column and key names follow `docs/NOTATION.md` (for example `mean_c_en`: the mean
energy cost C^en = min(E / E_ref, C^en_max) per task; `c_en_max` the cap).

## Not included

- The BDD100K frames used to measure the run times, and the YOLO weights: not ours to publish.
- The LuST SUMO scenario (cite Codeca et al. 2015).
- `points.lp` in each run folder: the InfluxDB feed for Grafana, a text copy of the Parquet tables (128 GB).
- Smoke runs and the testbed's `_test*` debugging folders.

## How to regenerate

```
uv sync --locked --all-extras
uv run python train.py --maps vfc --windows 6 --population 40 --generations 20 --budget 1000000
uv run python evaluate.py --maps vfc
uv run python run_testbed.py --maps vfc
```

The same config and seed give a bit-identical event log (tests/acceptance/test_m1.py pins its hash);
`tools/reproduce.py` reruns seed 3000 and compares with `summary.csv`. Built with `tools/export_dataset.py`.
