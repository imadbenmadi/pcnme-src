| Q6 | 2026-10-28 | M0.3 | Common random numbers (13.2): with one stream per purpose drawn in event order, a different NSGA-II plan changes the order of draws, so the same task gets a different run time in each plan. How are run times and delays drawn? | 28 Oct, Imed: keyed by task. A run time = a uniform u from a draw keyed by (purpose, task_id, attempt), mapped through the inverse CDF of the time-table row the task actually runs on, so the task keeps its quantile on any node or slot type. A delay is keyed by (purpose, task_id, attempt, link/hop). Keys hold nothing that depends on decisions besides the attempt number. Arrivals and mobility stay sequential per car.
