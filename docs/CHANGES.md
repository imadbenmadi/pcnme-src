| C4 | 2026-10-28 | 8.5 (and 8.3, 7.2, 11.1) | The pooled estimate Ŵ = (R + B) ÷ c treats a node's c_q slots as one server, so one long run is spread over every slot. When a 720 ms T2 holds one F-GPU slot and the other frees every 8 ms, Ŵ is about 2× the real wait: the web review measured, at S2 load on one F-GPU node with fixed run times, a T2 running at 69 % of arrivals, pooled Ŵ 193 ms against a real wait of 89 ms, and 60 % of those arrivals refused "late" on the GPU against 29 % really late. In S1–S3 (T2 a pebble) the executor refuses T1 and T3 it could run, and the agent's Ŵ input and its "can meet the deadline" mask are off by about 2× too. | Each node publishes the remaining time r_i of each of its c_q slots instead of their sum R; Ŵ is the time W at which the backlog B, poured onto the slots in the order they free up, fills them all: Σ max(0, W − r_i) = B (0 while a slot is free). Caveats (Claude Code review): it treats queued work as divisible, so it can underestimate by up to one task's run per slot (the hard estimate is no longer strictly on the safe side) and still overestimates for a soft newcomer queued behind a T2; each state message carries c_q numbers per slot type (32 for the cloud).
