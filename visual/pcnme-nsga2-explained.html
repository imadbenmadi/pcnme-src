1. The whole stage on one line

NSGA-II is the expert. It runs offline, before the agent learns anything. For short pieces of city traffic it searches for very good placement plans, and those plans become the agent's teacher.

Seed1000–1999, one per window
Warm-up5 s of greedy
Window2 s of tasks = genes
NSGA-II40 plans × 20 generations
Pareto frontthe unbeaten plans
Knee → wone weight per window
w*median over windows
Demonstrationsreplay every front plan
DQfDpretrain the agent

It answers two questions for the agent: which placements are good (the demonstrations) and how much time should weigh against energy (w*). The agent's reward uses the same two costs, so the expert and the agent chase the same goal.

2. Seeds: what a seed fixes

A scenario is a recipe (load, task mix, deadlines, zones on or off). A seed is one random draw of that recipe: which cars, which tasks, when, how long each runs, every link delay. Same scenario + same seed = exactly the same traffic, bit for bit.

Three separate seed ranges

1000–1999 NSGA-II + demos
2000–2999 training
3000–3999 evaluation

The ranges never overlap, so the agent is never tested on traffic it learned from or that the expert planned.

The seed of each window

seed = 1000 + 100 · (s − 1) + k     for scenario Ss, window k = 0 … 5

Click a cell to see what it means. Highlighted: S2 window 0, the example used through this page.

What the seed fixes, and the "same luck" rule

Every random draw has its own stream, all derived from the seed: arrivals, run times, link delays, mobility, and NSGA-II's own choices (the "nsga" stream). Inside a window, a task's luck is keyed by the task, not by the order of events:

run-time draw u = draw(seed, task id, attempt)   →   Trun = F−1row(u)

So task 57 gets the same u in every plan. If plan A runs it on a fog GPU and plan B on the cloud, both use the same u, mapped through the time-table row of where it actually runs. Delays work the same way, keyed by (seed, task id, attempt, hop). This is called common random numbers: when two plans score differently, the only reason is the placement, never luck.

3. The window: warm-up, 2 s, settle

  1. 0 → 5 s, warm-up (Twarmup = 5 s): the greedy rule places every task. At time 0 the city is empty; after 5 s the queues, slots and pipes are loaded like in a normal run. This part is the same in every plan.
  2. 5 → 7 s, the window (Twin = 2 s): every pebble (a task a fog node can run) whose upload arrives in this interval, anywhere in the city, is a window task. Each one becomes one gene. Boulders are not genes: the TOF-Broker always sends them to the cloud.
  3. After 7 s, settle: new tasks are placed by greedy again, so the last window tasks still see realistic load. The run stops once every window task has finished, been dropped or timed out. Nothing later affects the score.

4. One gene = one task's placement

A gene is a number: the index of the option chosen for one task, out of the options of the zone the task arrived in (its anchor):

0 here 1 Nb1 2 Nb2 3 Nb3 4 Nb4 5 cloud

These are the same 6 actions the agent has. "Nb1" means the anchor's nearest neighbour zone, not a fixed zone, so a gene only has meaning together with its task's anchor.

Task 57type T1 (object detection)anchor z2deadline D = 100 msarrived at 5.412 s

Empty positions are not options. If the anchor has fewer neighbours online (for example z5 still offline), the missing positions are left out of that task's gene. A gene can only take values that exist for its task, so it can never point at an empty position. This is the design's repair rule ("a gene pointing at an empty position is repaired to here"), done once, by construction.

Masked at run time: if a planned option turns out to be masked when the decision happens (for example the node is full or the car will leave the zone too soon), that one decision is made by greedy instead.

5. One plan = all genes of the window

A plan (also called a chromosome or genome) has one gene per window task, in a fixed task order. S2 window 0 has 294 tasks, so a plan is 294 numbers. Below, the first 60 genes of three plans:

greedy
energy-greedy
random

Each cell is one task; its colour is the option it is sent to. Illustration: these are not the real genes of window 0.

  • Greedy plan: each task goes where the estimated finish time is lowest (fastest). Mostly here, sometimes a neighbour.
  • Energy-greedy plan: each task goes to the open option with the lowest estimated energy Ê that still meets its deadline (cheapest).
  • Random plan: each gene drawn uniformly from its task's valid options.

How many plans exist? With up to 6 options per task and 294 tasks, up to 6294 ≈ 10229. Trying them all is impossible; NSGA-II tries 800.

6. Scoring a plan: f₁ and f₂

Evaluating a plan = one fast-mode simulation of the window with the plan's genes as the window tasks' first decisions. Queues, refusals, retries, aborts and drops all happen as in a real run, so putting many tasks on one node really makes them wait. Each task i gets two costs:

Task outcometime cost Ctimeienergy cost Ceni
delivered, latency LL/D + w3 · max(0, L − D)/D, with w3 = 1min(E/Eref, 9.197), E over all attempts
droppedCdrop = 1 + (1 + w3) · 1 + Cpen = 1 + 2 + 2 = 5Cenmax = 9.197
f1 = (1/N) Σi Ctimei      f2 = (1/N) Σi Ceni      both minimised, N = window tasks

Worked mini-example: 5 tasks

A drop is worse than any delivery in both costs, so the search can never "win" by letting tasks fail cheaply. There is no hard constraint on drops: under overload some drops can't be avoided, and a constraint would squeeze the front onto only the fewest-drop plans.

The problem in one line: find the plan a = (a1, …, aN) that minimises (f1(a), f2(a)). Fast plans cost energy, cheap plans are slower, so there is no single best plan, only a set of best trade-offs: the Pareto front.

7. The first 40 plans

NSGA-II doesn't start from pure chance. Half the first population is built from the two sensible plans:

row 1greedy plan
row 2energy-greedy plan
rows 3–20mutated copies, alternating
rows 21–40random valid plans
duplicatesnot allowed

A mutated copy = the greedy (or energy-greedy) plan with about 1 gene in 294 moved to another option (black outline). Because NSGA-II is elitist (it never throws away a plan unless a better one replaces it), no plan on the final front is dominated by the greedy plan: the expert is never worse than greedy on both costs at once.

Why not the DE mutation of the VFC paper? DE builds a new gene by arithmetic, V = X1 + F · (X2 − X3). PCNME genes are categories relative to each task's anchor: "Nb3 − Nb1" means nothing. So the mutation just moves a task to another valid place.

9. Keeping 40 of 80: ranks and crowding

After the 40 children are scored, there are 40 + 40 = 80 plans. NSGA-II keeps 40:

  1. Dominates: plan A dominates B if A is no worse on both f1 and f2, and better on at least one.
  2. Rank 1 = plans nobody dominates. Remove them; the plans now undominated are rank 2; and so on (non-dominated sorting).
  3. Fill the 40 places rank by rank.
  4. The rank that doesn't fit completely is cut by crowding distance: for each plan, the gap between its two neighbours on that rank, summed over both objectives (normalised). End points get infinite distance. The plans with the biggest gaps are kept, so the front stays spread out instead of bunching up.

11. The knee and the weight w

The final front's points have different scales (time costs near 0.4, energy costs near 1.0), so first both axes are rescaled to 0–1:

f̃j = (fj − fjmin) / Δfj,    Δfj = fjmax − fjmin

Knee = the point farthest from the straight line between the two end points. On 0–1 axes that line is f̃1 + f̃2 = 1, so the knee is the point with the smallest f̃1 + f̃2 (ties go to the faster plan). It is where you stop getting a big energy saving for a small time loss.

Slope at the knee, from its left neighbour p− and right neighbour p+ (one-sided at an end):

σ = (f̃2(p−) − f̃2(p+)) / (f̃1(p+) − f̃1(p−)),    w̃ = σ / (1 + σ)

σ is the exchange rate at the knee: how much normalised energy the front gives back for one unit of normalised time. A weighted sum w̃ f̃1 + (1 − w̃) f̃2 is lowest where the slope equals w̃/(1 − w̃); setting that equal to σ gives w̃ = σ/(1 + σ). The reward uses the raw costs, not the 0–1 ones, so the weight is taken back through the ranges:

w = (w̃ / Δf1) / ( w̃ / Δf1 + (1 − w̃) / Δf2 )

Worked example (invented 6-point front in the range of S2 window 0; numbers computed with the repo's knee.py)

  • No knee if the front has fewer than 2 distinct points: there is no range to rescale. That happened in 9 of 36 grid windows (S4 and S5), and 14 of 36 on LuST.
  • Every front point gets its own wp by the same formulas (last column). These are used for the demonstrations.
  • Limit: if the front isn't convex around the knee, no weighted sum picks exactly that point. The reward then asks for the nearest trade-off, while the margin loss still teaches the knee's actions.

13. From plans to demonstrations

Each plan on a window's front is replayed in the real simulator with the agent's input builder switched on. At every decision of a window task the replay records one transition:

( s, a, r, s′, Δt )    s = the 48 inputs with w = the plan's own wp,   a = the plan's gene,   r = the online reward
  • The replay is the real simulator, so s is exactly what the agent would see: stale state, pending sends, masks.
  • Expert flag: a transition whose action is the plan's gene is an expert transition; DQfD's margin loss pushes the agent toward these actions.
  • A gene masked at replay is replaced by greedy, and every greedy re-decision is stored without the flag (no margin loss).
  • Boulders make no transitions.
  • Besides the front plans, each window's greedy plan is also replayed (with w = w*).
