What happened

    The rules being animated

    A task arrives (Part C)

    For every slot type it can use (slots exist, a time-table row exists, a place is free for its class), the node estimates finish = wait + execution and puts the task in the queue that finishes earliest. Refused "full" if no usable queue has room (the last 2 places are for hard tasks only). Refused "late" if a hard task cannot meet its deadline, or a soft task cannot finish by deadline + L_max.

    A slot becomes free (Part D)

    1. Skip hopeless tasks at the head: hard past saving, soft later than L_max.
    2. Promote the first soft task if it waited ≥ A_max and no queued hard task would miss because of it.
    3. Else the first hard task (earliest deadline first).
    4. Else the first soft task.
    5. Else steal from the other queue a task that finishes earlier here.

    Drops (Part I)

    A running hard task is aborted when its deadline passes, a soft one at deadline + L_max. The worker stops at the end of its current step, so the slot stays busy up to d_abort (striped). Every refusal, skip and abort is reported to the anchor at once.

    Example numbers, not the thesis values (those are still open in the Math & numbers checklist): YOLO-L 40 ms on GPU / 150 ms on CPU, YOLO-S 14 / 42 ms, GPU-only 55 ms, Tracker 18 ms on CPU; a run takes 0.8–1.35 × its mean; hard deadline 90 ms, soft 220 ms; queue 6 places per slot type, 2 kept for hard; L_max 120 ms; A_max 150 ms; d_abort = 60% of the mean (the inference step).
