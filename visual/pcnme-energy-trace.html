The energy of every task in the latency trace, worked out with the energy model (section 4 of the Mathematical Models document, final design 12) and the numbers in the config. Same tasks, same placements, same real run times. Click a row to see its full calculation.

What is added up for each attempt

Ek = Efwdk + Eexeck,q + Eretk
Efwdsending the input to option k: here 0, neighbour ebhS, cloud (ebh + ewan)S Eexecrunning it: PUEk · P̄k,q · Trun Eretsending the result back: fog (2ebh + edown)Sres, cloud (ewan + ebh + edown)Sres

Only dynamic energy counts (busy power minus idle). Waiting in a queue or a pipe costs nothing. The car's upload is the same for every option, so it is reported, not part of the decision.

The constants

Reference energy Eref per task type

Eref = PUEfog · P̄ref · T̄runref + Erethere

The task run on its own standard fog node (GTX 1070), on its fastest slot type (the GPU). E / Eref = 1 means "as costly as running it here".

From energy to cost and reward

Cen = min(E / Eref, Cenmax)

r = rok − w · Ctime − (1 − w) · Cen

rok = 1, w = w* = 0.414 (VFC grid), Ctime = L/D + w3 max(0, L − D)/D. A dropped task gets Ctime = Cdrop = 5 and Cen = Cenmax.

What this example simplifies

The tasks, placements and real run times are those of the latency trace (seed 5, greedy placement, one zone with one neighbour and the cloud). Every task here is delivered in one attempt, so retries, refusals and aborts (final design 12.5) do not appear. Fog CPU power (41.7 W) is an estimate and the cloud powers (150 W GPU, 30 W CPU) are assumptions; fog GPU power is measured per task type. The reward uses w* = 0.414.
